# V0.10 targeted runtime recipe and tag probe
Launch the enabled native probe with JVM properties -Dmms.debug.recipe=namespace:id and/or -Dmms.debug.item_tag=namespace:id. The selected active RecipeManager entry and current item tag membership are sampled with the existing snapshot. Tag membership includes explicit size/truncation. Optional -Dmms.debug.recipe_experiment=true -Dmms.debug.recipe_input=minecraft:stone,minecraft:oak_planks performs an in-memory horizontal grid check of that exact recipe only. Disabled by default; only exact vanilla ShapedRecipe or ShapelessRecipe classes allowed. Mixins may still change vanilla implementation; use only trusted disposable test environments for the experiment. This is not GUI crafting, recipe-selection priority, item consumption, or resource transfer, and cannot prove arbitrary custom machine recipes. Match results may change after reload; snapshot timestamps must be checked. Native probe failure is explicitly unavailable, not false absence. Existing recipe diagnosis remains static/registry-based; runtime evidence is returned separately via game.recipe_status. Current local IDE protocol is vendor-independent JSONL, not MCP yet.

Validation: existing real production-JAR test uses data-only cross-JAR recipe, checks active server recipe, planks tag membership, and actual match/assemble yields a Studio-generated gem. Unit tests use synthetic snapshots. No completion claim until Java build and live CI pass.
