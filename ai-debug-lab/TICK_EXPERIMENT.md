# V0.5 controlled tick experiments
First active debugging slice: typed bounded step counts, no arbitrary commands, operating on the stdin of a dedicated server that the trusted test launcher just created in a disposable temporary directory. No active controls in the general IDE bridge yet; the Python boolean is an internal launcher contract, not a security boundary or proof a server is disposable. Never call against an existing player world. Actual command responses for observations must match the supported English 26.2 format.

The experiment verifies initially advancing game time, freezes, verifies a stable negative control, advances exactly 1, 5, and 20 ticks, checks that the world stops again and verifies recovery. Every command and observation is recorded. An overshoot, unsupported response, timeout or failed cleanup is invalid, not evidence of a mod defect. The launcher always stops/kills its disposable process on exit. The built-in tick freeze command is not a JVM breakpoint; players, networking and some mod code may still execute. No claims about deterministic replay, arbitrary machine state or full isolation.

CI: existing vanilla two-seed smoke and the standalone production-JAR Fabric smoke now include the experiment and save tick-experiment.json on success and failure. Unit fixtures are separate from live evidence. Sources: https://minecraft.wiki/w/Commands/tick and https://mcasset.cloud/26.2/assets/minecraft/lang/en_ca.json.
