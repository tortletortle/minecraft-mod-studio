## 3. Technical behavior

### 3.1 Static analyzer

The output schema is now 0.2 and the analyzer version is 0.2.0.

Mixin config output now distinguishes:
- mixinClasses: class names listed in the config;
- targetClasses: empty in static-only analysis;
- targetDiscoveryStatus: NOT_ANALYZED until annotation parsing is run.

Entrypoint objects preserve adapter and value separately. The analyzer also records declared nested JAR paths, aliases, conflicts and language adapters. Recursive nested-JAR inspection and access-widener directive parsing remain unimplemented.

### 3.2 ASM oracle

The Java helper reads framed class bytes from stdin and uses ASM 9.11.1 visitors. It does not create a class loader, define a class, initialize a class, or execute input code.

The differential harness compares:
- class name/version/superclass/interfaces;
- method name/descriptor/access tuples;
- invocation instruction multisets;
- invokedynamic counts.

The harness marks the run failed if a parser mismatch occurs, a class is not parsed by both parsers, or invocation comparison is skipped due to the 500-sample cap.

ASM also reads CLASS-retained @Mixin annotations. The enrichment step joins config-declared Mixin class names to parsed class names and returns target classes plus explicit unresolved-class evidence.

This is parser cross-checking, not JVM verification or runtime behavior validation.

### 3.3 ModIR

ModIR 0.1.0 is a provenance-first evidence graph. It records artifact identity, source profile, mods, dependencies, entrypoints, classes, Mixin configs, resources and evidence references.

Important constraints:
- ASM and static reports must have the same input SHA-256.
- A missing target mapping remains unknown; it is not marked unsupported.
- targetProfile remains null until a concrete target runtime/SDK/API profile is pinned.
- mappings remain empty.
- overall migration status remains UNASSESSED.
- no Rust code is generated.
