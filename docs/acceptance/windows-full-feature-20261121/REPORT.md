# Minecraft Mod Studio V2.5 / AI Debug Lab V0.12.2 Windows 实机验收

2026 年 11 月 21 日。模组制作到运行的主流程通过。全功能验收为部分通过，有四项问题已复现。

默认分支 main 固定在 8e8703875131c60b3bf2440c2dd8f44ae8c616a9。主入口为 Minecraft_Mod_Studio_V19.html，界面显示 V2.5。Windows 游戏客户端和 MCP 使用 PR #6 候选 3d265d533a412b453cc0b835b66a05c6f10126ad 的产物。默认分支另做 Chromium、Gradle 和真实 Minecraft 模型 API 对照。

环境为 Windows 11 build 26200、Python 3.12.10、Temurin 25.0.5+8、MCP Python SDK 2.3.0、Gradle 9.5.1、Minecraft Java 26.2、Fabric Loader 0.20.1、Fabric API 0.161.0+26.2。客户端使用 RTX 5060 Laptop GPU 和 OpenGL。浏览器使用 Chromium/Playwright。所有世界、缓存和会话均为本地隔离测试夹具。客户端加载原始发布 JAR，产品文件和个人存档均未操作。

第三轮无缓存中位数为 115.375 秒，预置缓存为 25.672 秒。第四轮热启动中位数约为冷启动的 14.1%。冷启动日志中 Fabric 下载和超时伴随长尾。轮询数据缺少单次请求精确分段，因果占比和完全离线能力尚未建立。

两个并发实例分别耗时 86.828 秒和 93.609 秒，最终共享缓存完整，世界、配置和会话隔离。缓存清单仅含 .fabric、libraries、versions 和 cache-manifest.json。篡改测试使同大小文件的 SHA-256 变化，触发拒绝和重建。复验新清单完整，未见暂存残留，下一次启动命中。原总表的 corrupt_recovery=false 来源于旧脚本额外要求新旧 ZIP 容器哈希相同。补充核查系统确认了条目内容相同和 ZIP 时间戳不同。

## 复现问题和建议

1. 启动过程中断开时，产品清理流程和 SDK 关闭宽限不匹配。将 JVM 结束、端口释放、临时目录移除纳入跨进程回归。首次残留目录的手工递归删除被执行工具以 blocked by policy 拦截。该 JVM 已退出，第二次残留由试验驱动清理。
2. 预算耗尽已正确拒绝写入。向调用方返回明确错误原因和剩余预算，并覆盖 set_block 和 tick_steps。
3. 归档路径校验和边界测试约定不一致。统一校验规则，再跑现有静态归档边界套件。
4. 默认分支会用状态动画覆盖同名行走/待机轨道。PR #6 上已有覆盖保护，可复用本轮同输入的 ModelPart 对照作为回归。

未覆盖的边界包括长时资源泄漏、跨模组包运行时联调、动画逐帧时序和全部图形设置。两次客户端使用测试身份，日志记录了在线服务 401 和正常本地启动、退出。Crystal Lab 的复制世界还含旧验收 datapack，因命名空间不同而报告一个函数加载错误。当前夹具的各成功标记在同一原始日志中可独立核对。
